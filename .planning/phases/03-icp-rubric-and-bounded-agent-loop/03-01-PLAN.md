<objective>
## Phase Goal

Every company gets a reproducible, defensible qualification verdict from a written ICP rubric, and insufficient data triggers a capped, logged agent loop instead of a guess.

User-story framing: not available. The ROADMAP Phase 3 Goal is phrased as an outcome, not a story, and MVP rules say not to invent one.

## This plan (tracer first)

This plan replaces the Phase 1 placeholder four-signal score with the real qualification slice. A rubric data file, hashed into every run, feeds a pure Python interval scorer that works on validated evidence. Its min/max verdict is wired into `run_one` as a `qualify` stage that stops disqualified and insufficient-data companies before Hunter, with the full breakdown in run.json and on screen. Task 1 is the end-to-end tracer: rubric file, loader and hash, scorer, stage, and run record, proven offline with the conftest fakes. Task 2 locks the scorer down with a calibration set written before any demo score is seen, plus determinism and rubric-validation tests. Task 3 makes the verdict visible: the printed breakdown, the rubric line in the summary, and the batch-level zero-Hunter guarantee. Plan 03-02 then adds the bounded research loop in the gray band.

Purpose: ROADMAP Phase 3 success criteria 1, 2, 3 and 5 (QUA-01, QUA-02, QUA-03, QUA-05).

Output: `config/icp.toml`, `src/outreach/qualify.py`, the Qualification models in `src/outreach/models.py`, `stage_qualify` in `src/outreach/stages.py`, rubric identity in `run_one` and `run_batch`, the calibration fixture and `tests/test_qualify.py`, and the two older tests that name the stage moved to `qualify`.

`src/outreach/qualify.py` (new; never imports the Gemini SDK; stdlib `tomllib`, `hashlib`, `re`):
- `DEFAULT_RUBRIC_PATH` is the repo-root `config/icp.toml`, resolved from this file (`Path(__file__).resolve().parents[2]`). The package is an editable install, so this resolves from both tests and the CLI.
- `RubricError(Exception)`. Pydantic rubric models: `Thresholds(qualify_min, reject_max, reference_year)`, `GateRule(id, label, field, fail_values: list)`, `KeywordGroup(points, keywords)`, `SignalRule(id, label, group, weight, kind: Literal["map", "best", "count", "keyword", "year_recency", "text_keyword"], field, attribute: str | None = None, points: dict[str, int] = {}, tiers: list[list[int]] = [], keyword_groups: list[KeywordGroup] = [], keywords: list[str] = [], observed_on: list[str] = [], target_kinds: list[str] = [])`, `PenaltyRule(id, label, points, requires: list[str], excludes: list[str] = [])`, `Rubric(version, description, thresholds, gates, signals, penalties)`, `LoadedRubric(rubric, sha256, path)`.
- `load_rubric(path=DEFAULT_RUBRIC_PATH) -> LoadedRubric`: read the bytes once; sha256 is the hex digest of those exact bytes; parse with `tomllib.loads` on the decoded bytes; validate with pydantic. Raise `RubricError` naming the problem when: the TOML or the schema is invalid, signal weights do not sum to 100, any signal's maximum attainable points differ from its weight, `qualify_min <= reject_max`, a signal or gate id repeats, or an observed_on or target_kinds value is not in `scrape.PAGE_KINDS`.
- `usable_kinds(pages) -> set[str]`: the `kind` of every page that passes `pagegate.is_usable`.
- `score_profile(profile, kinds_usable, rubric) -> RubricScore`, pure and deterministic. For each signal produce a `SignalScore` with status known (points_min equals points_max) or unknown (points_min 0, points_max equal to weight):
  - `map`: null field means unknown; otherwise the points for the value key, where a bool's key is "true" or "false" and any other value is its string; a key missing from the table gives known 0. Evidence is the field's quote and source_url.
  - `best`: the maximum points over list items by `attribute`. Evidence is the best item, where ties go to the item whose quote sorts first.
  - `count`: the points of the first tier whose minimum is at most the list length. Evidence is every item, sorted by quote.
  - `keyword`: for each item, the points of the first keyword group with a whole-word, case-insensitive match in the attribute text; take the maximum. A non-empty list with no match is known 0. Evidence is the matching items, sorted by quote.
  - `year_recency`: unknown when stage is null, as_of is null, or no 4-digit year (1900 to 2099) appears in as_of. Otherwise age = reference_year minus that year (a negative age counts as 0), scored as above. Evidence is the stage quote.
  - `text_keyword`: unknown when the field is null. Otherwise points when any keyword matches the value as a whole word, case-insensitive, else known 0. Evidence is the field's quote.
  - List kinds (best, count, keyword) on an empty list are known 0 when any `observed_on` kind is in kinds_usable, and unknown otherwise. Each SignalScore carries a short `basis` string, for example `status=in_progress`, `3 customers`, `no item; security page read` or `unknown: no security page read`.
  - Gates give a `GateResult` with status pass, fail or unknown (null field), plus a basis and evidence. Penalties normalise `framework + " " + quote` for each ComplianceMention with status certified: lowercase, drop every non-alphanumeric character, then replace "type2" with "typeii". A penalty applies when every `requires` token is a substring of some certified mention and no `excludes` token is. Applied penalties become `PenaltyHit` records. The output does not depend on list order: sort evidence as stated and evaluate penalties over a set.
  - `score_min = max(0, sum(points_min) - penalties)` and `score_max = max(0, sum(points_max) - penalties)`. `unknown_signals` holds the ids of unknown signals sorted by weight descending, then id.
- `initial_verdict(score, rubric)`: "disqualified" when any gate failed, else "qualified" when score_min >= qualify_min, else "disqualified" when score_max < reject_max, else "loop".
- `final_verdict(score, rubric) -> tuple[str, str]`: the same first three rules (reasons such as `gate G1_b2b failed: is_b2b=false`, `score_min 80 >= qualify_min 60`, `score_max 16 < reject_max 45`). In the gray band it returns "disqualified" with reason `score 48 known on every signal is below qualify_min 60` when unknown_signals is empty, else "insufficient_data" with reason `score 25..90 straddles reject_max 45 and qualify_min 60; unknown: <ids>`.
- `qualify(profile, pages, loaded) -> Qualification`: score with `usable_kinds(pages)`, record initial_verdict and initial_score, take verdict and reason from final_verdict on the same score (Plan 03-02 inserts research between the two), and set decided_with_unknowns to unknown_signals unless the verdict is qualified.

## STRIDE Threat Register

ASVS level 1; the block threshold is high. Every high threat is mitigated.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering (prompt injection steering the score) | `qualify.score_profile` | high | mitigate | The LLM never emits a number. Points come only from Python rules over facts that Phase 2's validator kept (quote verbatim on the cited page, instruction lines removed). Each signal is capped at its weight, so a planted claim can move the score by at most one signal's weight. Calibration and determinism tests prove the rules |
| T-03-02 | Tampering (rubric edited between runs without a trace) | `qualify.load_rubric`, `run_one`, `run_batch` | medium | mitigate | The sha256 of the exact file bytes and the version are written into every run.json (before stage 1), every Qualification, summary.json and the printed summary; `test_rubric_hash_changes_with_file_bytes` |
| T-03-03 | Elevation of privilege / cost (Hunter credit spent on unqualified companies) | `stages.stage_qualify` | high | mitigate | Every non-qualified verdict raises StopStage before the hunter stage; the batch test asserts FakeHunter.calls holds only the qualified domain |
| T-03-04 | Repudiation (a verdict nobody can defend) | Qualification record | medium | mitigate | Every gate, signal (points, status, basis, evidence quote and URL) and penalty is stored in run.json and printed; decided_with_unknowns names what was not known |
| T-03-05 | Tampering (malformed rubric silently mis-scores) | `qualify.load_rubric` | medium | mitigate | Load-time validation (weights sum to 100, each signal's max equals its weight, known kinds only, qualify_min above reject_max, unique ids) raises RubricError before any domain runs |
| T-03-06 | Tampering (terminal escape sequences in printed quotes) | `qualify.render_breakdown` | low | mitigate | Control characters are stripped from every page-derived string before printing; `test_render_breakdown_strips_control_characters` |
| T-03-07 | Repudiation (threshold tuned to make demo companies pass) | `config/icp.toml`, calibration fixture | medium | mitigate | Thresholds 60 and 45 are pinned by `test_repo_rubric_thresholds_are_pinned`; the calibration verdicts are recorded before any demo score is seen; any change needs a version bump and a visible test edit |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs: tomllib, hashlib and re are stdlib; pydantic was approved in Phase 1 |
