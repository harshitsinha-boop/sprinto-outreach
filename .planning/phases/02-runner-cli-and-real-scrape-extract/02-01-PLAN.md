## Phase Goal

User runs one command on a file of domains and each domain is safely scraped and turned into schema-validated, evidence-quoted company data, with one bad domain never stopping the batch.

User-story framing: not available. The ROADMAP Phase 2 Goal is outcome-phrased, not "As a / I want to / so that"; per MVP rules no story is invented here (run `/gsd-mvp-phase 2` to add one).

## This plan

Tracer slice for the whole phase: a text file of domains goes through a new `run` command, a batch runner, the existing six-stage `run_one` (scrape, extract, score, hunter, draft, send) and ends in a printed summary table, proven end to end offline with the Phase 1 fakes. The expansion task then adds the batch semantics RUN-02 and RUN-03 require: dead domains end as failed while the batch carries on, systemic failures (bad key, exhausted quota, send refusal) abort at once, dry run stays the default and `--send` is the only way to call Resend, plus input hygiene and a per-run cap. Plans 02-02 and 02-03 deepen the scrape and extract stages behind this runner without changing it.

Purpose: ROADMAP Phase 2 success criteria 1, 2 and 3 (RUN-01, RUN-02, RUN-03, RUN-04).

Output: `src/outreach/runner.py`, the `run` command in `src/outreach/cli.py`, outcome and batch models in `src/outreach/models.py`, `DomainUnreachable` in `src/outreach/stages.py`, and `tests/test_runner.py`, `tests/test_cli_run.py`.

The second return value is the list of rejected-line rows (empty in this task; Task 2 fills it).
- `STOP_OUTCOMES = {"insufficient_data", "no_contact", "disqualified", "rejected_draft"}` and `outcome_for(rec: RunRecord) -> tuple[str, str]` returning (outcome, detail): status `dry_run` gives `qualified` with detail `dry-run: email drafted, Resend not called`; status `sent` gives `sent` with detail `message id <id>` read from the send stage output; status `stopped` with a reason in STOP_OUTCOMES gives that outcome with the stopped stage's output detail (fall back to the reason); a stopped reason outside STOP_OUTCOMES gives `failed` with detail `unknown stop reason <reason>`; status `failed` gives `failed` with detail `<failed_stage>: <error of the failed stage>`; any other status gives `failed` with detail `run did not finish`. The returned outcome is always a member of OUTCOMES.
- `run_batch(domains, ctx, *, pre_rows=None, hunter_label="fixture", progress=None) -> BatchSummary`: create the summary with `mode` "dry_run" when `ctx.dry_run` else "send", `hunter=hunter_label`, `started_at=now_iso()`, rows starting from `pre_rows`; loop over the domains in order, calling `run_one(domain, ctx)` inside a per-domain `try/except Exception` (the isolation boundary: on an exception load the already-flushed record with `ctx.store.load(domain)` and map it with `outcome_for`; when no record exists use outcome `failed` and detail `redact(type name + ": " + message, ctx.settings)`); append a BatchRow with detail cut to 200 characters and `run_record=str(ctx.store.path_for(domain))`; when `progress` is given write one line `[i/N] <domain> -> <outcome>` per domain. At the end fill `counts` with every key of OUTCOMES (zero included) and set `finished_at`.
- `render_summary(summary) -> str`: plain text (not rich, so CliRunner output is stable): a header line `SUMMARY mode=<mode> hunter=<hunter>`, then a left-aligned table whose columns `domain`, `outcome`, `detail` are padded to the widest cell (detail cut to 80 characters), one row per BatchRow in order, then the line `outcomes: qualified=N disqualified=N insufficient_data=N no_contact=N rejected_draft=N sent=N failed=N` in OUTCOMES order, then `ABORTED: <abort_reason>` when aborted.
- `write_summary(summary, out_dir) -> Path`: `atomic_write_json(out_dir / "_batch" / "summary.json", summary.model_dump(mode="json"))` and return the path. The underscore directory can never collide with a domain directory, because a hostname cannot contain an underscore.
